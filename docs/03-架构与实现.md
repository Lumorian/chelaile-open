# 架构与实现

> 注：0.3.0 起主交付物是 apps/android（纯 Java 实现）；本文描述 TypeScript protocol/server/web 研究栈，两者共用同一套 H5 协议。

## 1. 分层

```
┌───────────────────────────────────────────────────────────────┐
│ apps/web        React 19 + Vite 8      手机优先 PWA 风格单页   │
│ apps/cli        Node 直跑 TS           终端调试 / 脚本化       │
├───────────────────────────────────────────────────────────────┤
│ packages/server node:http BFF          缓存、聚合、静态托管     │
│                 /api/*  →  上游 /api/*                         │
├───────────────────────────────────────────────────────────────┤
│ packages/protocol  领域层（零运行时依赖）                       │
│   client.ts  端点封装     aes.ts / md5.ts  纯 TS 密码学         │
│   envelope.ts 剥壳        geo.ts 坐标系      models.ts 展示模型 │
│   types.ts   类型         fixtures.ts 演示数据                  │
└───────────────────────────────────────────────────────────────┘
```

设计约束只有三条：

1. **协议层零依赖**。不引 axios、不引 crypto-js：`fetch` 是标准库，AES/MD5 手写并带 NIST/RFC 向量测试。这样 CLI 能单文件运行，协议层能被任何运行时复用（Node / Deno / Bun / 浏览器 / 边缘函数）。
2. **前端不直连上游**。上游要求固定 `Referer`、全量公共参数、且响应被 `**YGKJ` 包裹；浏览器直连会踩 CORS 与 header 限制（`Referer` 属于 forbidden header）。所有请求走同源 BFF。
3. **展示模型与传输模型分离**。`types.ts` 忠实映射线上 JSON（含 `[k: string]: unknown` 逃生口），`models.ts` 负责“给人看”——距离、到站文案、运营时间窗口。UI 只消费 `models`，改文案不影响协议。

## 2. 一次「附近线路」请求的完整链路

```
NearbyView            api.nearbyLines(city, lat, lng)
   │ GET /api/nearby/lines?cityId=241&lat=..&lng=..
   ▼
server/index.ts       handleApi → routes.nearbyLines
   ▼
routes.ts             cache.wrap("near:241:24.8138:113.5920", 15s, loader)
   │  同 key 并发请求只会打一次上游（promise 复用）
   ▼
client.ts             ChelaileClient.call("/api/bus/stop!encryptedNearlines.action", {...})
   │  ① 合并 H5 公共参数 ② 可选 cryptoSign ③ Referer/UA
   │  ④ fetch → ⑤ stripWrapper → ⑥ status 判定 → ⑦ AES 解密 → JSON.parse
   ▼
routes.ts             { data, cached:false, fetchedAt:"..." }
   ▼
api.ts                解包 Envelope，失败抛 ApiClientError
   ▼
NearbyView            group.lines.filter(l => l.lines.length > 0) → LineRow
   ▼
models.summarize()    stnStates → depIntervalM → shortDesc/desc → nextOperationTimeDesc
```

## 3. 协议层模块

| 文件 | 职责 | 关键点 |
| --- | --- | --- |
| `config.ts` | 常量 | Base URL、H5 公共参数、`SIGN_SALT`、`AES_KEY`（32 字节 ASCII）、UA、城市接口参数 |
| `http.ts` | `getText(url, {headers, timeoutMs, retries})` | `AbortSignal.timeout`；5xx/网络错误退避重试；非 2xx 抛 `HttpError` |
| `envelope.ts` | `stripWrapper(text)` | 兼容有/无包裹、前后空白、非 JSON 前缀（防止网关插广告串） |
| `aes.ts` | AES-256-ECB 解密/加密 | 纯查表实现；`expandKey` 由密钥长度推导轮数；PKCS#7 去补位 |
| `md5.ts` | MD5 | RFC 1321 全流程，处理 UTF-8 与 64 位长度 |
| `client.ts` | `ChelaileClient` | 端点方法 + `call()` 统一装配参数、剥壳、判错、解密 |
| `geo.ts` | WGS-84 / GCJ-02 / BD-09 | `stationToWgs()` 三级降级：服务端 wgs 字段 → `gpsType==="bd"` 转换 → 原样 |
| `models.ts` | 展示模型 | `summarize()` 的优先级就是“信息可信度”排序 |
| `fixtures.ts` | 演示数据 | 结构对齐真实响应，覆盖有车/无车/多段运营 |

### 3.1 为什么自己写 AES

不是为了炫技，而是三个现实理由：

- `node:crypto` 在浏览器里不存在，WebCrypto 的 AES-ECB **不支持**（规范只给 CBC/CTR/GCM）；
- 上游用 ECB 且密钥是 ASCII 常量，一旦要跑在 Cloudflare Workers / Deno Deploy，依赖 Node 内置模块会直接崩；
- 自实现可以精确控制 PKCS#7 的宽松程度（上游偶发返回尾部带 `\u0000` 的明文）。

实现上有一个值得记录的坑：**复合乘法表必须在 `MUL2` 全表填完之后再算**。最初把 `MUL2[i]=xtime(i)` 和 `MUL9[i]=MUL2[MUL2[MUL2[i]]]^i` 放在同一个循环里，读到的是尚未赋值的 0，导致解密全错、报“PKCS#7 填充非法”。测试用 NIST AES-256 向量 + `node:crypto` 双向对拍锁死。

### 3.2 `ChelaileClient` 的调用约定

```ts
const client = new ChelaileClient({ cityId: "241", lat: 24.813761, lng: 113.591965 });
const detail = await client.getLineDetail({
  lineId: "751135962641", lineName: "38", direction: 0,
  targetOrder: 10, stationName: "东堤中路", nextStationName: "风采广场（市一医院）"
});
```

- 城市/坐标是**客户端状态**（`setCity` / `setGeo`），每次请求自动带上；
- `call()` 对 `encrypted*` 自动解密，调用方拿到的永远是明文对象；
- `status !== "00"` 抛 `ApiError(status, errmsg, path)`，包含端点路径便于定位；
- `getLineDetail` 的 `cryptoSign` 默认计算但可关（服务端不校验，见协议文档 §3）。

## 4. BFF 层

```
GET /api/health
GET /api/cities
GET /api/locate?lat&lng
GET /api/lines?cityId&q&limit
GET /api/nearby/lines?cityId&lat&lng
GET /api/nearby/stations?cityId&lat&lng
GET /api/line/:lineId/route?cityId
GET /api/line/:lineId/detail?cityId&lineName&direction&stationName&nextStationName&lineNo&targetOrder
GET /api/station/:physicalStId?cityId&name
```

统一响应：

```json
{ "ok": true, "data": { }, "cached": true, "fetchedAt": "2026-11-08T04:20:00.000Z" }
```

错误：

```json
{ "ok": false, "error": "缺少参数 lat", "code": "400" }
```

- `BadRequest` → 400；上游 `ApiError` / 网络错误 → 502（`code` 透传上游 status，便于前端区分“参数错”和“上游挂了”）；
- 静态托管：命中 `apps/web/dist` 就发文件，未命中且无扩展名则回退 `index.html`（SPA 路由）；`/assets/*` 带一年 immutable；
- CORS 回显 `Origin` 并 `Vary: Origin`，方便 `vite dev` 之外的独立前端联调；
- 只允许 GET/HEAD，OPTIONS 返回 204。

### 4.1 缓存策略

```ts
const TTL = { cities: 6h, cityLines: 30m, route: 30m, near: 15s, station: 15s, detail: 15s };
```

`TtlCache` 的两个细节：

- **请求合并**：`wrap()` 把进行中的 promise 存进 `inflight`，同一 key 的并发请求共享结果。否则首页 7 个组件同时挂载会打出 7 次上游请求，上游会限流。
- **LRU 上限**：默认 500 条（server 用 800），超限淘汰最久未访问的 key。北京线路表一条就 1.5 MB，必须设上限。

缓存键包含 cityId 与保留 4 位小数的坐标：`near:241:24.8138:113.5920`。坐标精度过高会导致“走两步就换 key”，完全失去缓存意义。

## 5. 前端

### 5.1 状态模型

`store.tsx` 是手写的 Context store（`useState` + 若干 action 函数），规模控制在 280 行内，避免为 6 个页面引入状态库：

```ts
type Page =
  | { kind: "near" } | { kind: "search" } | { kind: "fav" } | { kind: "settings" }
  | { kind: "line"; lineId: string; name?: string; start?: string; end?: string }
  | { kind: "station"; physicalStId: string; name?: string };
```

- **URL 即状态**：`parseHash` / `toHash` 与 `hashchange` 双向同步，刷新/分享不丢页面（`#/line/751135962641?name=38&cityId=241`）；
- **持久化**：`localStorage` 存 `chelaile.city` / `chelaile.geo` / `chelaile.favs` / `chelaile.demo`；
- **跨页面刷新**：`refreshTick` 计数器 + `bumpRefresh()`，收藏变更、城市切换后各视图统一重取；
- **演示模式**：`setDemoEnabled()` 是模块级开关，`api.ts` 每个方法一行三元表达式即可切换数据源，不污染视图层。

### 5.2 刷新节奏

| 视图 | 周期 | 说明 |
| --- | --- | --- |
| 附近 | 20 s | 只在 `document.visibilityState === "visible"` 时递增 tick |
| 线路详情 | 15 s | 可一键暂停；停运时段顶部标签会显示“预测/静态”，提示数据非实时 |
| 站点详情 | 15 s | 同上 |
| 搜索 | 220 ms 防抖 | 本地过滤整城线路表，不走网络 |

所有轮询都在 `useEffect` 里返回 `clearInterval`，且依赖数组含城市与坐标——切城市立即重新拉取，不会出现“广州的坐标查韶关的站”。

### 5.3 交互细节

- 线路页自动把**离你最近的站**设为 `targetOrder`（`nearestIndex` + `stationToWgs`），用户在时间轴上点任意站可改目标；
- 到站文案三行结构：主文案（还有 3 站 / 即将到站 / 首班未发）、副文案（距离 / 首末班 / 发车间隔）、实时点（有 `stnStates` 才亮绿点）；
- 空态与错误态分开：空态给“换个城市试试”，错误态给“重试”按钮并保留旧数据（避免闪烁）；
- 深色模式跟随 `prefers-color-scheme`，颜色全用 CSS 变量。

## 6. CLI

```bash
node apps/cli/src/index.ts cities
node apps/cli/src/index.ts near --lat 24.8138 --lng 113.5920 --city 241
node apps/cli/src/index.ts search 38 --city 241
node apps/cli/src/index.ts line 751135962641 --city 241 --target 10
node apps/cli/src/index.ts station cce0085015124d9eb4c8fbe0b8299259 --name 东堤中路
```

- 直接 `import "../../../packages/protocol/src/index.ts"`——Node 22+ 的类型剥离让 TS 免编译运行；
- `pad()` 按 `charCodeAt > 255` 记 2 列宽，中文表头不会错位；
- 退出码：成功 0，任意异常（参数/网络/上游）统一 1 并把原因打到 stderr，便于脚本编排。

## 7. 测试策略

| 层 | 手段 | 覆盖 |
| --- | --- | --- |
| 密码学 | 标准向量 + `node:crypto` 对拍 | MD5 六组、AES 七种长度、真实线上快照解密 |
| 协议 | 固定 JSON 快照 | 剥壳、签名、base64、字段类型 |
| 展示 | 纯函数断言 | 三种到站文案分支、多段运营时间、坐标转换往返 |
| 端到端 | `CHELAILE_LIVE=1` | 城市→线路→站序→附近→站点详情全链路（5 例） |

离线用例**不触网**，因此可以在 CI 里跑；`live` 用环境变量隔离，避免上游波动把构建搞红。真实加密响应作为 fixture 提交（7,488 字节），保证“解密正确”这件事有回归保护，而不是靠人肉验证。

## 8. 扩展指南

### 加一个端点

1. `types.ts` 加返回类型（字段宁可选，不要猜）；
2. `client.ts` 加方法，走 `this.call(path, params, { encrypted: true })`；
3. `server/src/routes.ts` 加 TTL 与 loader，`index.ts` 挂路由；
4. `apps/web/src/api.ts` 加同名方法与 demo 分支；
5. `tests/live.test.ts` 加一条真实断言。

### 换域名 / 加签名

`CHELAILE_BASE_URL` 环境变量可覆盖 Base URL（用于自建反代或镜像）。若上游将来启用签名校验，`client.ts#cryptoSign` 已经按顺序拼参，只需在某处把 `SIGN_SALT` 换成动态值。

## 9. 已知取舍

| 取舍 | 原因 | 代价 |
| --- | --- | --- |
| 不做原生 App | 需求是“开源版本”，Web 覆盖成本最低 | 无后台推送、无桌面小组件 |
| 不做账号体系 | 上游 `/wow/user!login2.action` 涉及手机号与第三方登录 | 收藏仅存本地 |
| 不落库 | 实时公交数据 15 秒即过期 | 服务重启后冷启动 |
| 不支持地铁换乘 | `/transfer/transit!tripPlan.action` 参数未完全逆清 | 只做单线路 |
| 坐标以 WGS 为内部标准 | 浏览器定位天然 WGS，转换只在边界发生 | 每次渲染多一次三角运算（可忽略） |
