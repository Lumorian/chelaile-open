# 协议参考：web.chelaile.net.cn

> 本文是 `packages/protocol` 的规格说明。所有字段均来自**真实抓包**（2026-11-08，cityId=241 韶关），
> 加密/签名细节均经代码验证。示例中的省略号表示删减。

## 1. 基本约定

```
Base URL   https://web.chelaile.net.cn
方法       GET
编码       UTF-8，query 参数一律 URL 编码
响应包裹   **YGKJ{...}YGKJ##      ← 前置 **YGKJ，后置 YGKJ##
```

剥壳后的结构：

```json
{
  "jsonr": {
    "status": "00",
    "errmsg": null,
    "data": { }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `status` | `"00"` 成功；`"01"` 业务提示（如搜索无结果）；`"400"` 参数缺失；`"12009"` 版本过期；`"10002"`/`"15000"` 参数错误 |
| `errmsg` | 错误描述，可能为 `null` |
| `data` | 业务数据；加密接口里只有 `encryptResult` 一个字段 |

### 1.1 必备请求头

```
Referer: https://web.chelaile.net.cn/     ← encrypted* 接口必须，否则 400
User-Agent: <Android Chrome UA>            ← 建议伪装移动端
Accept: application/json, text/plain, */*
```

### 1.2 公共参数

| 参数 | 建议值 | 备注 |
| --- | --- | --- |
| `s` | `h5` | 端类型；用 `android` 会被要求升级 |
| `v` | `9.1.2` | H5 版本号 |
| `vc` | `1` | 版本码 |
| `src` | `wechat_shaoguan` | 渠道标识，可换，但换错可能降级数据 |
| `userId` | `browser_xxxxxxxx` | 匿名 ID，仅用于收藏等，可随机 |
| `h5Id` | 同上 | 与 userId 相同即可 |
| `sign` | `1` | 固定 |
| `cityId` | `241` | 城市 ID，见第 6 节 |
| `geo_lat` `geo_lng` | 用户坐标 | WGS-84 |
| `lat` `lng` | 同上 | 老参数，与 geo_* 同时传 |
| `gpstype` | `wgs` | 声明坐标类型 |

> 缺任一参数通常直接 `status=400` 且 `errmsg=null`，排查时请先对齐参数表。

## 2. 加密

`encrypted*` 接口的 `data` 形如：

```json
{ "encryptResult": "kJ3s...base64..." }
```

解密参数：

| 项 | 值 |
| --- | --- |
| 算法 | AES-256-ECB |
| 补位 | PKCS#7 |
| 密钥 | 32 字节 ASCII 字符串（见 `packages/protocol/src/config.ts` 的 `AES_KEY`） |
| 密文编码 | Base64（标准字母表，含 `=` 补位） |
| 明文 | UTF-8 JSON，结构与明文接口一致 |

TypeScript（本项目实现，零依赖）：

```ts
import { AES_KEY, aesEcbDecrypt, base64ToBytes } from "@chelaile/protocol";

export function decryptEnvelope(encryptResult: string): unknown {
  const plain = aesEcbDecrypt(new TextEncoder().encode(AES_KEY), base64ToBytes(encryptResult));
  return JSON.parse(new TextDecoder().decode(plain));
}
```

命令行验证：

```bash
node -e '
const { AES_KEY, aesEcbDecrypt, base64ToBytes } = await import("./packages/protocol/src/index.ts");
const b64 = process.argv[1];
console.log(new TextDecoder().decode(aesEcbDecrypt(new TextEncoder().encode(AES_KEY), base64ToBytes(b64))));
' "<encryptResult>"
```

> 注意：早期资料写的是 AES/ECB/PKCS5 —— PKCS5 与 PKCS7 在 16 字节分组下等价，不必纠结命名。

## 3. 签名（cryptoSign）

```
cryptoSign = md5( join("&", 按固定顺序拼接的 "k=v") + 盐 )
```

参与签名的业务参数（仅这些，顺序固定）：

```
lineId, lineName, direction, stationName, nextStationName, lineNo, targetOrder
```

**实测服务端不校验**：把 `cryptoSign` 替换成 `deadbeef` 依然返回 `status=00`。因此签名不是鉴权手段，仅保留实现用于对拍。

## 4. 端点

### 4.1 城市列表 `GET /cdatasource/citylist`

注意：这个接口**不用** H5 公共参数，用「老 App」参数。

| 参数 | 值 |
| --- | --- |
| `type` | `all`（全量）或 `gpsRealtimeCity`（按坐标反查） |
| `s` `v` `src` | `android` / `3.80.0` / `webapp_default` |
| `lat` `lng` `gpstype` | 仅 `gpsRealtimeCity` 需要，`gpstype=wgs` |

```bash
curl -sS 'https://web.chelaile.net.cn/cdatasource/citylist?type=all&s=android&v=3.80.0&src=webapp_default'
```

```json
{
  "data": {
    "allRealtimeCity": [
      { "cityId": "241", "cityName": "韶关", "pinyin": "shaoguan", "cityVersion": 20260101, "hot": 0, "supportSubway": 0 }
    ]
  }
}
```

- 共 **499** 个城市；
- **广州、深圳不在列表里**（该 App 在这两地由其它渠道提供数据）；
- `gpsRealtimeCity` 只返回 `cityName`，需要再用名称在城市表里反查 `cityId`。

### 4.2 城市线路表 `GET /api/bus/cityLineList`

| 参数 | 说明 |
| --- | --- |
| `cityId` | 城市 |
| `lineName` | **实测被忽略**，永远返回整城线路 |

```json
{
  "allLines": {
    "all": [
      { "lineId": "751135962652", "lineName": "1", "startStopName": "凤凰城总站", "endStopName": "森鑫汽车城", "firstTime": "06:20", "lastTime": "22:00", "tagName": "all", "tags": {}, "type": 0 }
```

### 4.3 线路站序 `GET /api/bus/line!lineRoute.action`

| 参数 | 说明 |
| --- | --- |
| `lineId` | 线路 ID |
| `cityId` | 城市 |

```json
{
  "route": [{ "lat": 24.832729, "lng": 113.597934, "stopOrder": 1, "distance": 0 }],
  "line": { "lineId": "751135962641", "name": "38" },
  "stations": [
    { "sId": "0751-131", "sn": "碧桂园（凤凰城）", "order": 1, "lat": 24.835545536397273, "lng": 113.60964314802776,
      "distanceToSp": 0, "gpsType": "bd" }
  ],
  "gpstype": "bd"

```

**坐标是 BD-09**（百度系）。与浏览器定位（WGS-84）直接比较会偏 500–800 米，本项目用 `geo.ts#stationToWgs` 统一。

### 4.4 线路实时详情 `GET /api/bus/line!encryptedLineDetail.action`（加密）

最“重”的接口，45 个顶层字段。必传业务参数：

```
lineId, lineName, direction, stationName, nextStationName, lineNo, targetOrder
```

`targetOrder` 是用户关注的站序（从 1 开始）；`stationName` 是该站名，`nextStationName` 是下一站名。

解密后（截断）：

```json
{
  "line": {
    "lineId": "751135962641", "name": "38", "lineNo": "2410075",
    "startSn": "碧桂园（凤凰城）", "endSn": "碧桂园（太阳城）",
    "direction": 0, "firstTime": "06:50", "lastTime": "17:20",
    "price": "2元", "stationsNum": 32,
    "desc": "首班车尚未发车", "shortDesc": "首班未发",
    "nextOperationTimeDesc": "首班预计 06:50 发车",
    "assistDesc": "", "state": -4, "hasBusInfo": false,
    "segTimes": [["06:50", "17:20"]],
    "realCityId": "241", "isSubway": 0, "judgeLine": 1
  },
  "stations": [{ "sId": "0751-131", "sn": "碧桂园（凤凰城）", "order": 1, "lat": 24.83, "lng": 113.60, "wgsLat": 24.82, "wgsLng": 113.59, "physicalStId": "…", "metros": [] }],
  "buses": [],
  "targetOrder": 12,
  "nearStnOrder": 12,
  "realData": false,
  "refreshInterval": 0,
  "intervalLeft": -1, "intervalRight": -1,
  "depIntervalM": -1, "depDesc": "",
  "predictionText": "", "predictionLink": "",

  "otherlines": [{ "lineId": "751135962642", "startSn": "碧桂园（太阳城）", "endSn": "碧桂园（凤凰城）" }],
  "roads": [], "traffic": 0, "toast": ""
}
```

字段语义要点：

| 字段 | 含义 |
| --- | --- |
| `desc` / `shortDesc` / `assistDesc` | 三种粒度的状态文案；有实时车辆时 `assistDesc` 才有值 |
| `nextOperationTimeDesc` | “首班预计 06:50 发车”，运营开始前才有 |
| `segTimes` | 分段运营时间，多段线路（如高峰线）会有多组 |
| `state` | `-4` 未发车 / `1` 运营中（观测值） |
| `refreshInterval` | 服务端下发的刷新间隔（秒），0 表示无需轮询 |
| `buses` | 车辆数组；凌晨无车时为空 |
| `tip` | 每日一句（真的），UI 可以展示 |

## 5. 错误与异常处理建议

| 场景 | 建议 |
| --- | --- |
| `status=400` + `errmsg=null` | 90% 是缺参数或少了 `Referer` |
| 解密失败 | 先确认 key 是 32 字节 ASCII，再确认 base64 没被截断 |
| `buses`/`stnStates` 为空 | 正常（夜间/停运）；UI 必须准备兜底文案 |
| 城市不在列表 | 换最近的有数据城市，或用坐标反查 |
| 302/502 | 上游偶发，重试 2 次即可 |

## 7. 请求频率约定

| 端点 | 建议 TTL | 理由 |
| --- | --- | --- |
| 城市列表 | 6 小时 | 极少变化 |
| 城市线路表 | 30 分钟 | 大响应（北京 1.5 MB），毒化缓存代价高 |
| 线路站序 | 30 分钟 | 静态 |
| 附近线路 / 站点详情 / 线路详情 | 15 秒 | 到站信息的最小刷新粒度 |

本项目 BFF 的 `TTL` 常量见 `packages/server/src/routes.ts`，并对同 key 的并发请求做了合并（`TtlCache#wrap`），避免多端同时刷新击穿。

## 8. curl 速查

```bash
BASE='https://web.chelaile.net.cn'
COMMON='s=h5&v=9.1.2&vc=1&src=wechat_shaoguan&userId=browser_demo&h5Id=browser_demo&sign=1&cityId=241&geo_lat=24.813761&geo_lng=113.591965&lat=24.813761&lng=113.591965&gpstype=wgs'
UA='Mozilla/5.0 (Linux; Android 13) Chrome/116 Mobile Safari/537.36'

# 站序
curl -sS "$BASE/api/bus/line!lineRoute.action?lineId=751135962641&cityId=241&$COMMON" -H "User-Agent: $UA" -H "Referer: $BASE/"

# 附近线路（加密）
curl -sS "$BASE/api/bus/stop!encryptedNearlines.action?cityState=2&$COMMON" -H "User-Agent: $UA" -H "Referer: $BASE/"
```
